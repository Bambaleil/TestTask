# Платёжный модуль

Модуль отвечает за сущность платежа, идемпотентное создание, вызов провайдера,
сохранение результата, уведомление клиента и три прикладные попытки.

## Бизнес-инварианты

1. Один `Idempotency-Key` соответствует одному нормализованному запросу.
2. Новый платёж и событие обработки фиксируются атомарно.
3. Финальный результат оплаты не изменяется из-за сбоя доставки webhook.
4. Обработанное событие не создаёт новую оплату или дополнительный retry.
5. У всех повторов одного webhook сохраняется `event_id`.
6. Третья неуспешная попытка приводит к долговечному событию DLQ.

`PaymentRepository.create()` проверяет отпечаток тела и возвращает существующий
платёж при повторе. При конкурентной вставке DAO сообщает о конфликте;
repository читает победивший платёж в новом Unit of Work.

`PaymentProcessor.process()` фиксирует результат провайдера отдельной
транзакцией до отправки HTTP-уведомления. При ошибке уведомления следующая
попытка использует сохранённый результат и не запускает оплату заново.
Завершение текущего события и создание retry/DLQ сохраняются атомарно.

## Замена провайдера

Реализуйте `PaymentGateway.charge(Payment) -> PaymentStatus` и передайте адаптер
в `PaymentModule.build()`. Провайдер должен использовать `Payment.id` как
внешний ключ идемпотентности. Эмулятор из `dao/gateway.py` стабилен для UUID
и задерживает обработку на 2–5 секунд.
